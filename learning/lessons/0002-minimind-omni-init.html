Lesson 0002 · Constructor Map

拆解 MiniMindOmni 初始化：一张多模态装配图

第一课追踪调用链，本课回答每个对象在哪里创建，以及它们如何共享维度。

完成标准

你能从 MiniMindOmni.__init__ 解释父类模块、Omni 新增模块、别名、Projector 和可选编码器的职责。

装配顺序

OmniConfig -> super().__init__ -> thinker alias -> talker -> projectors -> optional encoders

构造函数负责接线，权重通常由 load_state_dict 在外部注入。

配置与父类

OmniConfig 增加 audio_hidden_size、image_hidden_size、talker_hidden_size、audio_vocab_size、image_token_len。super().__init__(config) 创建文本主干 self.model 与 self.lm_head。

object.__setattr__(self, 'thinker', self.model) 只是别名；self.thinker is self.model，不会复制参数。

Talker 与 Projector

TalkerModule 内部包含音频 Embedding、Transformer blocks、TalkerHead、codec 和说话人投影。Thinker 负责语义，Talker 负责生成音频 codes。

MMAudioProjector(audio_hidden_size, hidden_size); MMVisionProjector(image_hidden_size, hidden_size)

Projector 是跨模态接口适配层：外部编码器的特征维度不同，必须统一到 Thinker 的 hidden_size。

外部编码器

load_sensevoice 与 load_vision 在路径不存在时返回 None；成功时加载处理器与编码器，并设置 eval()、requires_grad=False。因此对象结构与外部权重是否存在是两件事。

动手定位

  1. 打开 model/model_omni.py 定位构造函数。
  2. 确认 self.thinker 与 self.model 同一对象。
  3. 读出两个 Projector 的输入、输出维度。
  4. 找到编码器冻结代码。

检索练习

问题 1：为什么 audio_proj 输入不是 hidden_size？

它接收音频编码器的原始特征，输入是 audio_hidden_size，输出才是 hidden_size。

问题 2：thinker 会复制模型吗？

不会，它只是 self.model 的别名。

问题 3：为什么编码器冻结？

它们充当固定特征提取器，不参与当前模型训练。
