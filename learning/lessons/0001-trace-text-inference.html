第二站：init_model() 把结构和权重合在一起

eval_omni.py:17 中，原生 PyTorch 路径依次完成：

  1. 从 model/ 加载 tokenizer。
  2. 根据参数构造 OmniConfig。
  3. 用配置实例化 MiniMindOmni，此时只有模型结构。
  4. 从 out/sft_omni_768.pth 读取状态字典并写入结构。
  5. 加载 Mimi codec，切换半精度、评估模式和 CUDA 设备。
ckp = f'./{args.save_dir}/{args.weight}_{args.hidden_size}{moe_suffix}.pth'
model = MiniMindOmni(OmniConfig(...), ...)
model.load_state_dict(torch.load(ckp, map_location=args.device), strict=False)
...

torch.load 读取磁盘对象，load_state_dict 才把参数复制进已经创建的模型结构。参见 PyTorch 官方的 torch.load 与 load_state_dict 文档。

第三站：eval_sample() 把对话变成张量

eval_omni.py:43 中的数据形态依次变化：

messages: list[dict]
    ↓ tokenizer.apply_chat_template(...)
inputs_text: str
    ↓ tokenizer(inputs_text)
input_ids: list[int]
    ↓ torch.tensor(...)[None, ...]
x: LongTensor[1, sequence_length]

apply_chat_template 不是分词。它先按照模型训练时的对话格式，把角色和内容拼成字符串；随后 tokenizer 才把字符串转成 token id。可对照 Hugging Face 官方的 Chat templates。

第四、五站：进入 Omni 生成循环

eval_sample() 调用的是 MiniMindOmni.generate()。因为传入 stream=True，它立即返回 stream_generate() 生成器。

eval_sample()
└─ model.generate(..., stream=True, return_audio_codes=True)
   └─ MiniMindOmni.generate()
      └─ MiniMindOmni.stream_generate()
         └─ self.forward(...)
            ├─ text logits
            └─ audio logits

生成循环每一步读取最后位置的 logits，采样一个文本 token，并维护音频 codes。具体采样和 Talker 细节留到后续课程；今天只需要定位这条边界。

检索练习

先不翻上文，用自己的话回答，再核对答案。

问题 1：--weight sft_omni 为什么最终会读取 sft_omni_768.pth？

因为 init_model() 用权重前缀、隐藏维度和可选的 MoE 后缀拼接检查点路径。

问题 2：apply_chat_template() 和 tokenizer 分别做什么？

前者把消息列表格式化成模型训练时使用的对话字符串；后者把字符串转换成 token id。

问题 3：为什么本次调用会进入 stream_generate()？

因为 eval_sample() 调用 model.generate() 时显式传入了 stream=True。
